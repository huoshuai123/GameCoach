# Android 工程架构

## 目标

Android 工程是第一阶段优先产品形态，用来验证雀魂 AI 复盘教练是否有完整、顺手、有教练感的移动端体验。

工程实现必须保留清晰边界：Android 负责交互和展示，复盘模型、报告 schema 和评估逻辑尽量保持平台无关。

## 分层

### UI 层

职责：

- 牌谱导入入口。
- 对局列表或样例列表。
- 复盘报告总览。
- 关键决策点详情。
- 加载、空状态、错误状态。

边界：

- 不直接解析牌谱。
- 不直接写评估规则。
- 只消费 Domain 层提供的展示模型或报告对象。

### Domain 层

职责：

- 定义 `Situation`、`Metric`、`DecisionPoint`、`EvaluationReport`。
- 定义 `GameAdapter` 接口。
- 定义复盘用例，例如导入牌谱、生成报告、读取报告详情。

边界：

- 不依赖 Android Activity、Fragment、Compose 或 ViewModel。
- 不保存平台专属路径。
- 作为未来迁移到其他端时优先复用的核心层。

### Data 层

职责：

- 读取本地样例牌谱。
- 管理未来文件导入或分享链接解析。
- 将外部输入转换为 Domain 层可消费的数据结构。

边界：

- 第一阶段不做账号登录。
- 第一阶段不做实时数据抓取。
- 外部链接解析必须先经过合规和稳定性评估。

### Evaluator 层

职责：

- 基于结构化牌谱识别关键决策点。
- 计算效率、危险度、攻守判断等指标。
- 生成解释和训练建议。

边界：

- 第一阶段可以先用规则和样例特征验证“教练感”。
- 后续可替换为模型服务、本地推理或混合评估。
- 输出必须符合 `review-report-schema.md`。

## 数据流

1. UI 层触发导入。
2. Data 层读取并解析牌谱输入。
3. `MahjongSoulAdapter` 将牌谱转换为通用局势模型。
4. Evaluator 生成 `EvaluationReport`。
5. Domain 用例返回报告。
6. UI 层展示报告总览和决策点详情。

## 页面建议

- 样例牌谱页：列出可导入样例和解析状态。
- 报告总览页：展示本局总结、指标和关键训练重点。
- 决策点列表页：按优先级展示 3-5 个关键点。
- 决策点详情页：展示玩家选择、推荐选择、原因和训练建议。

## 测试重点

- 样例牌谱能导入。
- 解析失败时给出可理解错误。
- 报告总览展示核心指标和训练重点。
- 决策点详情不丢失 schema 必填字段。
- Evaluator 输出能被 UI 层稳定消费。
