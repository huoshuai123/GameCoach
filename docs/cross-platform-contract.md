# 跨端迁移契约

## 目标

跨端迁移契约用于保证雀魂 AI 复盘教练从 Android 迁移到 Web、桌面、iOS 或服务端时，不需要重写核心复盘能力。

Android 是第一阶段优先产品形态，但领域模型、报告结构和评估边界必须保持平台无关。

## 平台无关能力

以下能力必须独立于 Android UI 和系统 API：

- 牌谱输入转换为游戏局势模型。
- `Situation`、`Metric`、`DecisionPoint`、`EvaluationReport` 等领域对象。
- `GameAdapter` 接口和雀魂 adapter 的核心转换逻辑。
- 关键决策点评估逻辑。
- 报告 schema 和字段语义。
- 训练建议生成逻辑。

## 平台相关能力

以下能力可以由不同端分别实现：

- 文件选择、分享导入和本地权限。
- 页面导航和视觉展示。
- 本地缓存位置。
- 错误提示样式。
- Android 通知、快捷入口等系统集成。

平台相关层只能调用领域层能力，不应反向污染领域模型。

## 数据契约

所有跨端数据交换优先使用 JSON 兼容结构：

- 字段名使用稳定的 snake_case 或既有语言层统一约定。
- 枚举值使用可读字符串，例如 `efficiency`、`risk`、`attack_defense`。
- 新增字段必须向后兼容，旧端可以忽略未知字段。
- 已进入 Demo 的字段不随意改名；确需改名时必须保留兼容映射。

## GameAdapter 契约

每个游戏 adapter 负责：

- 接收该游戏的原始或中间格式输入。
- 输出通用 `Situation` 和可评估的局势序列。
- 标注游戏特有上下文，例如局、巡目、分数、势力、地图等。
- 将游戏术语转换为玩家能理解的报告文本。

adapter 不负责：

- Android UI 展示。
- 文件权限处理。
- 服务端鉴权。
- 多端缓存策略。

## EvaluationReport 契约

所有端展示同一份报告时，必须保留以下语义：

- `summary` 是玩家先看的结论。
- `metrics` 是解释局势的辅助指标。
- `decision_points` 是报告主体，每局默认 3-5 个。
- `training_focus` 是下一局可执行的训练重点。

展示层可以调整布局、折叠方式和排序视觉，但不能改变字段含义。

## 迁移验收

未来迁移到新端时，至少满足：

- 同一份样例牌谱在新端能生成语义一致的报告。
- 关键决策点数量、优先级和必填字段不丢失。
- 新端不要求修改 `review-report-schema.md` 的既有字段语义。
- 新端平台代码可以替换 UI 和导入方式，但不重写核心评估模型。

## 当前默认

- Android 是第一阶段唯一优先实现端。
- Python 原型作为算法和 schema 验证层保留。
- 其他端只通过文档和契约预留，不在第一阶段实现。
- 多游戏扩展只保留 adapter 边界，不提前实现第二个游戏。
